## 1. 功能①：简历解析导入

### 1.1 设计决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 解析方式 | 调用户自配 AI（BYOK） | 任意格式简历无法用本地规则解析；项目已有完整 AI 链路 |
| 输入格式 | Phase A：粘贴文本 + .txt/.md/.html/.htm；Phase B：PDF（vendor 内置 pdf.js） | HTML 简历（在线简历页导出/另存）用 options 页原生 DOMParser 抽文本，零新依赖；pdf.js 只能以本地静态文件引入（MV3 CSP 禁远程脚本） |
| 隐私边界 | **此功能例外**：简历原文会发往用户自己的 AI 端点，UI 必须明示 | 与主功能"值不出本机"不同，需显著提示 |
| 结果落地 | 渲染进现有资料编辑器，人工复核后点"保存资料" | 复用 `renderProfileSectionEditor` + 既有保存路径，AI 解析结果绝不直接落库 |

### 1.2 数据流

```
用户粘贴简历文本/选择文件
  → options.js 读取文本
     · .txt/.md：FileReader 直读
     · .html/.htm：DOMParser 解析 → 剔除 script/style → 按块级元素保留换行抽文本
     · .pdf：pdf.js 抽文本（Phase B）
  → OJAF_PARSE_RESUME { resumeText }
  → background.js buildResumeParseMessages() → callAi() → parseJsonFromText()
  → normalizeParsedResume() 归一化为 profileV2
  → 返回 options.js → renderProfileSectionEditor(profileV2) 渲染
  → 用户人工复核/修改 → 点"保存资料"（既有逻辑落库）
```

### 1.3 改动清单

| 文件 | 改动 |
|---|---|
| `src/options.html` | "导入"区新增：`从简历导入（AI 解析）`按钮 + 文件选择（.txt/.md/.html/.htm/.pdf）+ 粘贴文本 textarea + 隐私提示文案 |
| `src/options.js` | `importResumeFromText()` / `importResumeFromFile()`；`extractTextFromHtml()`（DOMParser 去 script/style、按块级标签保留换行）；调 `OJAF_PARSE_RESUME`；结果渲染进编辑器；未配置 API 时禁用并提示 |
| `src/background.js` | 新消息 `OJAF_PARSE_RESUME`；`buildResumeParseMessages(resumeText)`；`normalizeParsedResume(parsed)` |
| `vendor/pdf/`（Phase B） | 放入 `pdf.min.js` + `pdf.worker.min.js`；options.html 以本地 `<script>` 引入 |
| `README.md` / `README.en.md` | 新功能说明 + 隐私例外说明 |

### 1.4 AI Prompt 设计要点（buildResumeParseMessages）

- System：你是简历结构化引擎，输出严格 JSON，禁止输出 JSON 以外内容
- 给出**完整 profileV2 schema**：15 个内置 section key + 各 section 已知字段 key 清单（直接从 `sample-profile.json` 提取作为 few-shot 模板）
- 归一化规则：日期统一 `YYYY-MM`/`YYYY-MM-DD`；性别/是否题枚举归一；无法归入内置 section 的信息 → `customSections`（kind: simple/repeat）
- 缺失字段**不要编造**，留空
- 防护：resumeText 超长截断（约 20k 字符）；AI 返回 schema 不符时报错重试一次

## 2. 功能③：问答记忆（缺失信息自动记忆）

### 2.1 核心洞察

上游已有两个可白嫖的机制：
1. **customSections 自动进入 AI 匹配目录**（content.js L3082 + prompt 明示支持 `customFields.*`）——把记住的问答写进一个名为"问答记忆"的 customSection，**AI 语义匹配链路零改动**直接复用
2. **橙色待处理字段已被收集**（浮动面板 + `getControlCurrentValue()`）——"记住"入口直接挂在现有 UI 上

因此本功能 = **1 个新存储区 + 1 个保存入口 + 1 个本地快车道匹配 + 1 个管理页**。

### 2.2 数据模型

```js
// chrome.storage.local 新增顶层 key
learnedQA: [{
  id: "qa_xxx",              // 自增或 uuid
  question: "是否接受调剂",    // 原始问题文本
  normQuestion: "是否接受调剂", // normalizeText() 归一化后
  answer: "是",
  controlKind: "radio",       // text/textarea/select/radio/checkbox/date
  options: ["是","否"],        // 选择类控件当时的选项
  hostname: "xyz.com",        // 来源站点（用于同站优先）
  createdAt: 1690000000000,
  usedCount: 3,               // 复用次数
  promoted: true              // 是否已提升到 customSections
}]
```

### 2.3 数据流

**保存（页面 → 存储）：**
```
自动填写完成 → 浮动面板列出橙色待处理字段
  → 用户在页面上手动填好某字段
  → 面板中该字段旁点"记住"按钮
  → content.js getControlCurrentValue() 读取当前值
  → OJAF_SAVE_LEARNED_QA { question, answer, controlKind, options, hostname }
  → background.js 双写：
     a) learnedQA 数组（去重：同 normQuestion 更新 answer + usedCount）
     b) 提升到 profileV2.customSections["qa-memory"]（kind: simple, values[question]=answer）
```

**复用（两条通道）：**
```
通道1·快车道（免费、离线可用）：
  buildAutofillPlan 时，对未匹配字段用 normalizeText(label) 精确匹配 learnedQA
  → 命中即生成高置信度候选（同 hostname 加权优先）→ 直接填，不调 AI

通道2·AI 语义道（零改动）：
  customSections["qa-memory"] 已在资料目录里
  → 同一问题的不同措辞（"能否接受岗位调动"）由 AI 语义匹配命中
```

### 2.4 改动清单

| 文件 | 改动 |
|---|---|
| `src/content.js` | ①浮动面板待处理列表加"记住"按钮与已记住标记；②`buildAutofillPlan` 前插入 learnedQA 精确匹配快车道；③`normalizeText()` 复用 |
| `src/background.js` | 新消息 `OJAF_SAVE_LEARNED_QA` / `OJAF_DELETE_LEARNED_QA` / `OJAF_LIST_LEARNED_QA`；双写逻辑（learnedQA + customSections 提升） |
| `src/options.html/.js/.css` | 新增"问答记忆"管理区：列表、编辑、删除、随资料导出 |
| `README.md` / `README.en.md` | 功能说明 |

### 2.5 护栏

- **绝不学习**：文件上传字段、密码类型字段
- **声明类是否题**（"是否同意背景调查"等）：可学习但标记为"每次需人工确认"（复用现有 confidence 降级机制）
- 记忆值全部本机存储，与项目隐私定位一致；导出资料备份时包含 learnedQA

## 4. 测试策略

- **夹具测试**：把目标站点真实表单页"另存为 HTML"做 fixtures，本地起静态服务加载扩展反复测（避免反复操作真实网申页面）
- **回归基准**：`sample-profile.json` 作为已知良好数据
- **记忆复用验证**：同一站点同一表单跑两次——第二次待处理字段应显著减少
- **AI 兜底验证**：不配 API 时纯本地规则 + 快车道仍可用

## 5. 风险与注意

| 风险 | 应对 |
|---|---|
| 上游持续更新导致 fork 分歧 | 本地 remote 保留 upstream 指原仓库，定期 rebase/cherry-pick |
| 问答记忆膨胀导致 AI prompt 过长 | 后续给 customSections["qa-memory"] 做容量上限（按 usedCount/最近使用淘汰） |
| 简历解析发原文给 AI 的隐私例外 | UI 显著提示；仅用户显式点击触发；不配置 API 时功能禁用 |
| 学到的错误答案被反复复用 | 管理页可编辑/删除；填写后仍有绿色标记供人工复核（项目本身不自动提交） |
